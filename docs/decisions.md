# Decisions

Dated decisions for this repo, newest last.

- 2026-11-16: created from the ops starter kit, area `co-plugins`.
- 2026-11-17: **Why this plugin exists.** The owner decided on a routed contact page for Captive Origins (the owner's decision of 2026-11-16, named in the pull request): a search box that completes from many topics with synonyms, quick tiles, one short form, mail to one group address per topic with the sender as reply-to, and no group address shown on the page. The plugin is built agnostic: it knows nothing of any one site, and the site supplies topics, tiles and email.
- 2026-11-17: **Options, not an admin collection.** Topics and routes are options in code. Reasons: a route is an address mail goes to, so changing one should go through review and deploy, not an admin form; there is nothing to store, so no collection, access rules or migrations to maintain; and tests and the start-up checks (bad ids, bad addresses, tiles pointing nowhere) can refuse a broken config before it runs. Cost: a topic change needs a deploy. A later version could add an optional collection that feeds the same options if sites ask for it.
- 2026-11-17: **No stored submissions.** The email to the group inbox is the only copy. No collection, no log of messages. The built-in rate limiter keeps hashed keys and counts in memory only.
- 2026-11-17: **Honeypot gives a normal success answer.** A bot learns nothing from the reply. The attempt still counts against its address.
- 2026-11-17: **Limiter is in-memory by default, replaceable.** It suits one server. Serverless sites need `rateLimit` backed by shared storage, and the README says so. Anything other than `true` from a limiter, or a throw, refuses (fail closed). Requests with no address share one count.
- 2026-11-17: **The sender's name is cleaned, not trusted.** Line breaks and Unicode line separators in name or email are refused. Quotes, angle brackets, commas and semicolons are removed from the name before it is used in the reply-to and subject.
- 2026-11-17: **The component is a subpath, React is an optional peer.** `@extantape/payload-plugin-contact-tiles/react` holds the component, so the server side imports no React. It ships its own small CSS with variables, so a site can retheme it.
- 2026-11-17: **No-JS fallback is the default render.** The server markup is a select, tile links and a form that posts to the endpoint, which redirects back with `?sent=1` or `?error=`. The script upgrades it. Cost: a short flash from select to search box on first load.
- 2026-11-17: **Optional human check hook (owner choice).** The owner chose an optional `verifyHuman` hook, the same shape as in the sign-up plugin, for Turnstile or similar. Off unless the site sets it. It runs after the address count and the honeypot and before validation, routing or sending. Only exactly `true` passes; false, a throw, a rejection or any other value refuses with 400 `human` and a message that gives no reason. The token comes from `humanTokenField` (default `humanToken`), and the no-JS form post carries it like any field. The component has a `humanCheck` slot for the widget. No verifier is bundled.
- 2026-11-17 (open question): the package name is `@extantape/payload-plugin-contact-tiles`, as the owner's task gave it, while the shared standards still say `@captiveorigins` until the move completes.
- 2026-11-24: **Every autocomplete is smart (owner).** The owner's words, relayed from the Captive Origins side: "each and every autocomplete that looks at a field is \"smart\" -- so it should recognize each of the synonyms of a field, if any, irregardless of space, characters, etc". Topic search matches labels and synonyms with spaces, punctuation, case and accents ignored, matches word initials for a single token, and ranks exact, then prefix, then the word tiers. No fuzzy matching, so results stay predictable. After security review: a word matches only inside one word, repeated words count once, and only the first 200 characters and 12 distinct words are searched, so a pasted block cannot stall the page.

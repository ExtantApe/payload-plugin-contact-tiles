# Changelog

## Unreleased

- First version, 0.1.0. A Payload plugin that adds `POST <path>` (default `/contact`) and `GET <path>/topics`, and a React component at `/react`. Topics, synonyms, routes and tiles come from options. The server routes by topic id only, refuses unknown topics, sends through Payload's email adapter with the sender as reply-to, and stores nothing. Honeypot, per-address and per-email rate limits that fail closed, and refusal of line breaks in the name and email. The component is an ARIA 1.2 combobox with a no-JS fallback (select, tile links, redirecting form post).
- New: optional `verifyHuman({ token, address, req })` (the sign-up plugin's shape) and `humanTokenField`. Off unless set. It runs after the address count and honeypot and before validation, routing or sending; only exactly `true` passes, and a refusal (400 `human`) never says why. The component takes a `humanCheck` slot, and the no-JS post forwards the token.
- Fixed after review: no forwarded header is trusted by default (`trustProxy` picks `'x-forwarded-for'` or `'x-real-ip'`), so a spoofed `X-Real-IP` no longer resets the count. The built-in limiter is capped at `maxKeys` (50000) and refuses new keys when full. The address is counted before the body is read; bodies over 64 KB and multipart are refused. `verifyHuman` has a timeout (`verifyTimeoutMs`, 10 s) and refuses on timeout or a token over 2048 characters. New optional `rateLimit: { store }` with `hit(key, windowMs)`; a store that throws refuses the send. The README says the in-memory limit is per instance. The release job runs `npm ci --ignore-scripts` and pins npm 11.15.0.

Tested: 99 tests (81 server, 18 component); the 9 new ones cover the spoofed headers, the key cap, the size and multipart refusals, the streamed cutoff, the human check timeout and token cap, and the store (counts, throws, bad count). Earlier: 90 tests (72 server, 18 component). Server: routing, unknown topics, client-supplied addresses ignored, validation, header injection, honeypot, limits and fail-closed limiter, no-JS redirects, the human check (off, true, token and address and request reach the hook, false, throw, rejection and non-true values refuse, no reason given, the no-JS post), nothing public carries an address, option errors, search. Component: server-rendered no-JS markup, combobox roles and keys, announcements, tiles, the form, refusals. Ten guards were mutation-checked and each fails a test when removed. Not tested: a real Redis or database store, a real proxy, a body streamed from a real network, the release workflow (not run), a real site, a real email adapter or mail delivery, a real screen reader, a phone browser, contrast measured with a tool, several server processes.
